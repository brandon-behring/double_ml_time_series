## What constitutes a replay

| Evidence | What we checked | What it establishes |
|---|---|---|
| Published replays, historical questions and forward applications | Reran each driver on the isolated snapshot with checksum-verified input files. Compared numerical fields, strings and array membership with each corresponding historical CLI transcript. | Repeatability of the computations exposed by that driver. Identification and transport remain separate study-specific questions. |
| Rolling simulations | Checked the full-size results against the prior transcripts and reran the original output-writing commands. Compared files from the 500-replication, 999-resample bootstrap with the published table. | Whether the seeded calibration and its error measures recur. Multiple origins on one simulated path contribute one independent path to a paired comparison. |
| Prospective studies | Replayed the cricket issuance at its original timestamp and verified the original roster. Replayed the GSS issuance from its pinned historical data. Compared frozen forecast files and issuance digests. | Integrity of the pre-issued forecasts. Forecast performance awaits eligible future outcomes. |
| Classical and matched-method studies | Recomputed the earnings, panel, fiscal, impulse-response and paired simulation controls and the two pricing studies. Compared regenerated results with their historical records. | Numerical reproduction and, for simulations, performance against specified truth. A matched empirical coefficient alone supplies no observed causal ground truth. |
| 401(k) full historical refit | Started with zero joint files and an empty legacy directory, using the source revision, R library builds and seed rule of the historical run. Match completed rows on panel, folds, partition and learner. Count each seven-method partition only after R atomically publishes a valid final file. | Same-seed numerical repeatability of the seven author-code specifications. The authors' original published partitions were unavailable. |

The registry comparison uses relative and absolute tolerances of `1e-9` for JSON numbers and exact matching for labels and other outputs. The direct-file comparison hashes uncompressed content for gzip archives. The replay distinguishes preserved forecast files from freshly regenerated output. Variable worker counts and elapsed seconds are excluded from the matched-simulation metadata comparison. The code manifest fingerprints the snapshot's Python and R sources, project definition and dependency lock, including uncommitted drivers. ## The 401(k) computation

Each partition uses seven learner outputs on the 9,915-person sample. Two- and five-fold fits are repeated for 100 partition seeds across the homogeneous eligibility, interactive eligibility and participation-IV analyses. A cached nuisance fit generated during this execution can resume its own interrupted partition. The worker receives no predictions or scores from the previous audit. The supporting author code and installed libraries are shared read-only. The 50-core admission target and 16 GiB memory reserve apply across the host, so concurrent work can reduce actual worker counts. Individual R and numerical-library workers use one thread. [Original methods and timings](../2026-11-19_time_series_dml/07-401k-replication.md) · [Resource-aware dispatcher](../2026-11-19_time_series_dml/dispatch_401k.py)

When the Python lasso bootstrap ran concurrently, the two studies shared the 16 GiB host reserve. A live, PID-validated heartbeat gave the Python workers up to 2.5 GiB for incremental growth. The R coordinator subtracts that claim only when admitting a new fit. At the handoff all 17 R workers retained their process IDs and start times. The scheduler recorded 36.70 GiB available and budgeted 21.47 GiB for the growth of existing R fits. Under those conditions it admitted zero additional R workers. [Admission wrapper](reproduction/shared_dispatch.py) · [Handoff receipt](reproduction/resource-handoff.json)

Three code choices matter when interpreting a matching result. The author’s interactive “Best” branch overwrites each selected index with one, so it repeats rigorous lasso. In the participation-IV branch, the rule can trim observations with one learner’s eligibility propensity and weight them with another’s. Its reported SE also conditions on the estimated first stage. The earlier single-partition decomposition held the estimate fixed at **$12,253.72** and obtained SEs of **$1,795.84** under the author calculation and **$1,802.04** using the full ratio influence function. The author code also selects “Best” across the same outer folds used to score effects. Applications seeking an independent check on learner selection can choose the learner inside each outer training set and evaluate prediction and the causal score on the untouched fold. [Source-level mechanisms and fixed-prediction decomposition](../2026-11-19_time_series_dml/07-401k-replication.md) · [Pinned score and selection code](https://github.com/VC2015/DMLonGitHub/blob/b91cbf96c01eccd73367fbd6601ecdd7aa78403b/Moment_Functions.R#L228-L350)

It recorded zero failed partitions, up to 19 simultaneous fits and a minimum of 31.76 GiB available host memory. The 600 partition files recorded 273.09 cumulative hours of fit time. ## Reproduction commands

From the repository root, choose a new work directory on a filesystem with space for partial R fits. The setup takes the existing pinned author source and R builds from the path selected with `--r-assets`. The previous audit documents their setup. The preparation step starts the dispatcher and records its PID. Mutable study outputs are written under the isolated run directory.

```bash
audit=docs/audits/2026-11-21_evaluation_methods/reproduction
run=results/evaluation-reproduction-fresh
old=docs/audits/2026-11-19_time_series_dml
.venv/bin/python "$audit/prepare.py" "$run"
.venv/bin/python "$run/snapshot/$old/external/run.py" --suite all --jobs 10 > "$run/registry.log"
.venv/bin/python "$audit/registry.py" "$run/snapshot" "$run/registry.log" --output "$run/comparison" --require-complete
.venv/bin/python "$audit/refit.py" "$run/401k" --output "$run/comparison" --follow
```

All seven supplementary commands passed. The twelve regenerated rolling artifacts match their archived content, including the complete calibration draws and the expanded bootstrap table. [Supplementary results](reproduction/supplement.json)

The supplementary source and rolling checks use the Italian authors' pinned Python 3.12 environment, the original cricket ZIP, and the survey and vintage sources. `supplement.py` accepts the cache path and `--italy-python` and runs the corresponding full commands, saving its output receipts alongside the comparisons. To include a recovered registry job, pass the successful retry transcript after the initial one when invoking `registry.py`.
