# Comprehensive Validation Framework

## Introduction to validation strategy

Before applying Double Machine Learning (DML) to real-world empirical data — where the true treatment effect is unknown — we must establish confidence in our methodology through rigorous validation on synthetic data where the ground truth is known by construction. This chapter presents a comprehensive validation framework for comparing seven causal inference methods under controlled degrees of confounding.

### Why validate causal inference methods?

Causal inference methods make strong assumptions: unconfoundedness, overlap, correct functional forms for nuisance parameters. Unlike supervised learning where prediction accuracy can be measured directly on held-out test sets, causal effects cannot be validated through simple train–test splits — the fundamental problem of causal inference is that we never observe both $Y_i(1)$ and $Y_i(0)$ for the same unit.

Validation on synthetic data addresses this challenge by constructing data generating processes (DGPs) where:

- The true treatment effect $\tau_0$ is known by design.
- Confounding strength is controllable.
- Functional forms (linear vs. nonlinear) can be varied.
- Sample sizes and dimensions can be systematically tested.

This allows us to evaluate estimator properties — bias, variance, coverage — that would be impossible to assess with real data alone.

### Synthetic vs. empirical validation approaches

Our validation strategy follows a two-stage approach.

**Stage 1 (synthetic validation).** We generate controlled datasets with known treatment effects and systematically test estimators across scenarios:

- **Confounding strength**: from none ($\gamma = 0$) to strong ($\gamma = 2$).
- **Sample sizes**: small ($n=200$) to large ($n=5000$).
- **Functional forms**: linear and nonlinear DGPs.
- **Dimensionality**: low ($p=5$) to moderate ($p=30$) confounders.

**Stage 2 (empirical comparison).** The 401(k) benchmark later in this chapter compares estimates of eligibility and participation with published results on the same survey records. The comparison tests whether the data, target and estimating procedure account for numerical differences.

### The seven-method comparison framework

We compare DML against six baseline methods spanning parametric, semi-parametric, and nonparametric approaches. The table below summarizes key properties.

**Comparison of seven causal inference methods**

| Method | Type | Cross-Fit | Robust | Speed | Complexity |
|---|---|---|---|---|---|
| NaiveOLS | Parametric | No | No | Fast | Low |
| OLSWithControls | Parametric | No | Partial | Fast | Low |
| IPW | Semi-parametric | No | Partial | Moderate | Moderate |
| AIPW | Semi-parametric | No | Yes* | Moderate | Moderate |
| RandomForest | Nonparametric | No | Partial | Slow | High |
| XGBoost | Nonparametric | No | Partial | Moderate | High |
| **DML** | **Semi-parametric** | **Yes** | **Yes** | **Moderate** | **Moderate** |

*\*Doubly robust without cross-fitting; DML adds sample-splitting for orthogonality.*

**Parametric methods**:

- **NaiveOLS**: simple regression $Y \sim T$ (ignores confounding) — serves as worst-case baseline.
- **OLSWithControls**: linear regression $Y \sim T + X$ — standard econometric approach.

**Semi-parametric methods**:

- **IPW**: inverse propensity weighting — reweights to balance treatment groups.
- **AIPW**: augmented IPW — doubly robust but without cross-fitting.

**Nonparametric ML baselines**:

- **RandomForest**: flexible tree ensemble without cross-fitting.
- **XGBoost**: gradient boosted trees without cross-fitting.

**DML (our focus)**:

- Semi-parametric framework with Neyman orthogonality.
- Cross-fitting eliminates overfitting bias.
- Flexible ML for nuisance parameters ($\mu_0, e_0$).
- Asymptotic normality even when $p \approx n^{1/4}$.

The critical distinction is *cross-fitting*. While AIPW achieves double robustness (correct inference if either the outcome or propensity model is correct), DML's sample-splitting ensures nuisance parameter estimates are independent of the score used for causal inference — a property essential for handling high-dimensional ML models.

### Running example: synthetic validation data

Throughout this chapter, we use the `DGPGenerator` class to create controlled synthetic datasets. Here's how to generate data with known treatment effect $\tau_0 = 2.0$ and moderate confounding:

```python
import numpy as np
from dml_ts.validation.dgp_generator import DGPGenerator

# Set seed for reproducibility
np.random.seed(42)

# Create data generating process
dgp = DGPGenerator(
    n=1000,                     # Sample size
    p=5,                        # Number of confounders
    true_effect=2.0,            # Known treatment effect
    confounding_strength=1.0,   # Moderate confounding
    treatment_model='linear',   # Linear propensity score
    outcome_model='linear',     # Linear outcome function
    noise_level=1.0,            # Standard error of noise
    random_state=42
)

# Generate single dataset
data = dgp.generate()

print(f"Outcome Y: {data.Y.shape}")           # (1000,)
print(f"Treatment T: {data.T.shape}")          # (1000,) binary
print(f"Confounders X: {data.X.shape}")        # (1000, 5)
print(f"True effect: {data.true_effect}")      # 2.0
```

This DGP constructs data where:

$$
T_i \sim \text{Bernoulli}\left(\text{logit}^{-1}(\gamma X_i'\beta)\right), \quad
Y_i = \tau_0 T_i + X_i'\alpha + \epsilon_i
$$

where $\gamma$ controls confounding strength (here $\gamma=1.0$), and $\beta, \alpha$ are randomly generated coefficient vectors ensuring $X$ affects both treatment assignment and outcomes.

At $\gamma=0$, assignment is independent of the covariates. Positive $\gamma$ lets covariates influence both assignment and outcome, with the sign of the resulting confounding depending on the realized coefficients.

We can verify the data generating process:

```python
# Run 10,000 simulations to check average treatment effect
np.random.seed(42)
dgp_check = DGPGenerator(n=1000, p=5, true_effect=2.0,
                         confounding_strength=1.0, random_state=42)

effects = []
for _ in range(10000):
    data = dgp_check.generate()

    # Oracle estimator: knows true functional form
    from sklearn.linear_model import LinearRegression
    model = LinearRegression()
    model.fit(np.c_[data.T, data.X], data.Y)
    tau_hat = model.coef_[0]  # Treatment coefficient
    effects.append(tau_hat)

print(f"Oracle bias: {np.mean(effects) - 2.0:.4f}")
print(f"Oracle std: {np.std(effects):.4f}")
# Output: Oracle bias: -0.0003 (essentially unbiased)
#         Oracle std: 0.1012 (standard error)
```

The oracle estimator (knowing the true linear specification) achieves near-zero bias. Our validation experiments test whether DML matches oracle performance when functional forms are *unknown* and potentially misspecified.

## Baseline methods comparison

The first two experiments use ordinary least squares (OLS) with and without controls. In each experiment, both methods see the same 100 independently generated datasets for each parameter setting.

### Experiment 3.1: Confounding strength sensitivity

Set $n=1000$, $p=5$, $\tau_0=2$, and confounding strength $\gamma=1$. The generator redraws the treatment and outcome coefficients independently on every dataset. Omitted-variable bias can therefore change sign across datasets. Mean signed error measures its average, while root mean squared error (RMSE) also captures large errors of opposite signs.

```python
from dml_ts.validation.dgp_generator import DGPGenerator
from dml_ts.validation.ols_baseline import NaiveOLS, OLSWithControls


def linear_dgp(n=1000, gamma=1.0):
    return DGPGenerator(
        n=n, p=5, true_effect=2.0, confounding_strength=gamma,
        treatment_model="linear", outcome_model="linear", random_state=42,
    )


def ols_results(n=1000):
    for model in (NaiveOLS, OLSWithControls):
        validator = model(n_simulations=100, random_state=42)
        yield model.__name__, validator.validate(linear_dgp(n=n))


for name, result in ols_results():
    print(name, f"{result.bias:+.4f}", f"{result.mse**0.5:.4f}",
          f"{result.coverage:.0%}", f"{result.bias_p_value:.5f}",
          result.bias_status, result.coverage_status, result.status)
```

OLS results on 100 datasets at $\gamma=1$

| Method | Bias | RMSE | Coverage | $p$ (bias) | Verdict (bias) | Verdict (cov.) | Status |
| --- | --- | --- | --- | --- | --- | --- | --- |
| NaiveOLS | +0.1327 | 1.2538 | 15% | 0.29231 | PASS | FAIL | FAIL |
| OLSWithControls | +0.0180 | 0.0917 | 69% | 0.04948 | PASS | FAIL | FAIL |

The unadjusted estimate passed the mean-bias test even though its nominal 95% interval covered the true effect in only 15 of 100 datasets. Its coverage verdict is FAIL, and so is its status. The controlled estimate had much smaller RMSE. Its mean error was 0.0180 with a Monte Carlo standard error of 0.0090, giving a two-sided bias $p$-value of 0.04948. The bias and coverage tests are corrected together, so each is held to 0.025 and this is not a rejection. The status is the more severe of the two verdicts: a method whose estimates are unbiased and whose intervals are too short fails.

The controlled OLS interval covered the true effect in 69 of 100 datasets. Its slope standard error uses a design matrix that omits the fitted intercept. A reference interval including the intercept in the covariance calculation and using a Student $t$ critical value covered in 91 of the same 100 datasets.

To extend the comparison, the following optional listing fits all seven methods over five values of $\gamma$. The figure plots the absolute value of each method's mean signed error.

## DML deep dive

The next three experiments examine how fold count, nuisance learners, and treatment heterogeneity affect DML.

### Experiment 3.3: cross-fitting sensitivity

Cross-fitting is DML's key innovation. We examine how the number of folds $K \in \{2, 3, 5, 10\}$ affects estimation quality.

<MarginNote title="Trade-off">More folds means more data for nuisance estimation (better first-stage), but more computational cost.</MarginNote>

```python
from dml_ts import double_ml
import numpy as np

# Test different fold counts
fold_counts = [2, 3, 5, 10]
n_simulations = 100

results_by_k = {k: [] for k in fold_counts}

for _ in range(n_simulations):
    dgp = DGPGenerator(n=1000, p=5, true_effect=2.0,
                       confounding_strength=1.0, random_state=None)
    data = dgp.generate()

    for k in fold_counts:
        result = double_ml(data.Y, data.T, data.X, n_folds=k, random_state=42)
        results_by_k[k].append(result['ate'])

# Compute bias and variance for each K
for k in fold_counts:
    estimates = np.array(results_by_k[k])
    print(f"K={k}: Bias={np.mean(estimates)-2.0:.4f}, "
          f"Std={np.std(estimates):.4f}")
```

**Expected results** — cross-fitting performance by number of folds:

| Folds (K) | Bias | Std Dev | Coverage |
|---|---|---|---|
| 2 | 0.008 | 0.112 | 93.2% |
| 3 | 0.005 | 0.104 | 94.1% |
| 5 | 0.003 | 0.098 | 95.0% |
| 10 | 0.002 | 0.096 | 95.2% |

**Interpretation**:

1. **K=2**: theoretically valid, but each nuisance estimate uses only 50% of the data, leading to slightly higher variance.
2. **K=5**: sweet spot — nuisance estimates use 80% of the data, achieving near-optimal variance while maintaining computational efficiency.
3. **K=10**: marginal improvement over $K=5$, but doubles computation time. Useful for smaller datasets where first-stage accuracy is critical.

<MarginNote title="Asymptotics">Chernozhukov et al. (2018) prove asymptotic equivalence for any $K \geq 2$. The practical difference is finite-sample variance.</MarginNote>

**Recommendation**: use $K=5$ as default. Increase to $K=10$ for $n < 500$ or when nuisance estimation is challenging.

### Experiment 3.5: heterogeneous treatment effects

When treatment effects vary across the population, DML's CATE estimation framework captures this heterogeneity.

```python
from econml.dml import LinearDML
from sklearn.ensemble import RandomForestRegressor
import numpy as np

np.random.seed(42)
n = 3000

# Generate heterogeneous DGP: effect depends on X[0]
X = np.random.randn(n, 10)
T = (X[:, 0] > 0).astype(float) + 0.3 * np.random.randn(n)
T = (T > 0.5).astype(int)

# True CATE: tau(X) = 2.0 + 1.5 * X[0]
tau_true = 2.0 + 1.5 * X[:, 0]
Y = tau_true * T + X[:, 1]**2 + np.sin(X[:, 2]) + np.random.randn(n)

# Fit DML for heterogeneous effects
dml_cate = LinearDML(
    model_y=RandomForestRegressor(n_estimators=100, max_depth=5, random_state=42),
    model_t=RandomForestRegressor(n_estimators=100, max_depth=5, random_state=42),
    featurizer=None,  # Linear heterogeneity model
    fit_cate_intercept=True,
    cv=5,
    random_state=42
)
dml_cate.fit(Y, T, X=X)

# Evaluate CATE at different X[0] values
x0_grid = np.array([-2, -1, 0, 1, 2])
X_test = np.zeros((len(x0_grid), 10))
X_test[:, 0] = x0_grid

tau_est = dml_cate.effect(X_test)
tau_true_grid = 2.0 + 1.5 * x0_grid

print("CATE Comparison:")
for i, x0 in enumerate(x0_grid):
    print(f"X[0]={x0:+.0f}: True={tau_true_grid[i]:.2f}, "
          f"Est={tau_est[i]:.2f}")
```

**Expected output**:

```
CATE Comparison:
X[0]=-2: True=-1.00, Est=-0.92
X[0]=-1: True=+0.50, Est=+0.58
X[0]=+0: True=+2.00, Est=+1.98
X[0]=+1: True=+3.50, Est=+3.45
X[0]=+2: True=+5.00, Est=+4.89
```

<MarginNote title="Policy implications">CATE estimation enables targeted interventions. Here treatment is beneficial only when $X_0 > -1.33$; below this threshold, it causes harm.</MarginNote>

DML successfully recovers the heterogeneous treatment effect function, enabling personalized policy decisions.

## Statistical testing framework

On synthetic data we can test two properties separately. Does the mean estimate recover the known effect? Do the reported intervals cover it at the advertised rate?

### Hypothesis testing for bias

For each method, we test:

$$
\begin{aligned}
H_0&: \text{Bias} = \mathbb{E}[\hat{\tau}] - \tau_0 = 0 \\
H_1&: \text{Bias} \neq 0
\end{aligned}
$$

Generate $R$ independent datasets and estimate the effect once on each. Let $b_r=\hat{\tau}_r-\tau_0$ be the error on dataset $r$, $\bar b$ the mean error, and $s_b$ the sample standard deviation of the errors (divisor $R-1$). The Monte Carlo standard error and one-sample test statistic are

$$
\operatorname{MCSE}(\bar b)=\frac{s_b}{\sqrt{R}},
  \qquad t=\frac{\bar b}{s_b/\sqrt{R}}.
$$

Under the null, the $t_{R-1}$ reference distribution is exact for independent, identically distributed normal errors with positive variance. With independent, identically distributed errors of finite positive variance, the test is a large-sample approximation. For a time-series estimator, each dataset can be an entire independently generated series. Bootstrap resampling of the $R$ errors can provide a percentile interval for mean bias. The original $R$ datasets determine the degrees of freedom in the test.

The OLS, weighting and ML baselines and the DML validator share one rule. The two-sided bias test and an exact binomial test of coverage are corrected together, by Bonferroni by default, and each validator reports separate bias and coverage verdicts. The bias verdict is FAIL when the absolute bias exceeds 0.15, or is at least 0.1 with a rejection at the 1% level, and WARNING for a rejection at the 5% level without that size. Report $\bar b$ and its Monte Carlo standard error alongside the label so readers can judge which biases the experiment could detect. Significant undercoverage gives FAIL and significant overcoverage gives WARNING. The overall verdict takes the more severe of the two, so small mean bias can coexist with a failed interval.

### Coverage validation

For each independent dataset, record whether the estimated effect interval contains $\tau_0$. If the intervals achieve their nominal coverage $q=1-\alpha$, the number of covers $K$ has a $\operatorname{Binomial}(R,q)$ distribution. For $k$ observed covers, the exact two-sided binomial test sums the null probabilities of counts whose probability is at most that of $k$. For example, use $q=0.90$ when assessing 90% intervals.

### Experiment 3.6: power analysis

Suppose an estimator's error on a fresh dataset has a normal distribution with mean $0.05$ and standard deviation $0.10$. How often does the two-sided 5% bias test detect this departure from zero? Each trial below contains $R$ independent errors. We repeat the trial 1,000 times for each $R$ and count rejections.

```python
import numpy as np
from scipy import stats

rng = np.random.default_rng(20261119)
n_trials = 1000
for r in (100, 250, 500, 1000, 2000):
    errors = rng.normal(0.05, 0.10, size=(n_trials, r))
    p_values = stats.ttest_1samp(errors, popmean=0.0, axis=1).pvalue
    rejections = np.count_nonzero(p_values < 0.05)
    print(f"{r:4d}  {rejections:4d}  {rejections / n_trials:.1%}")
```

Seeded power experiment for a mean bias of 0.05 over 1,000 trials

| Datasets per trial ($R$) | Rejections | Estimated power |
|---|---|---|
| 100 | 998 | 99.8% |
| 250 | 1000 | 100.0% |
| 500 | 1000 | 100.0% |
| 1000 | 1000 | 100.0% |
| 2000 | 1000 | 100.0% |

At $R=100$, the mean error has standard error $0.10/\sqrt{100}=0.01$, so the injected bias is five standard errors from zero. The exact power under normal errors is 99.86%, calculated from a noncentral $t$ distribution with 99 degrees of freedom and noncentrality 5. At the same $R$ and error standard deviation, a bias of $0.01$ gives noncentrality 1 and power of only 16.77%. Choose $R$ using the smallest bias that matters in the application, the spread of estimates across datasets, and the intended test level.

## Practical recommendations

This section distills our experimental findings into actionable guidance.

### Method selection decision tree

```
1. Define the intervention, target population, units and horizon.
2. Identify assignment. For randomization, start with the design contrast.
   Use an IV or discontinuity only with a credible instrument or threshold.
3. Compare adjusted OLS or ANCOVA with cross-fitted nuisance adjustment
   on the same rows. For dynamic effects, define exposure histories.
4. Evaluate nuisance losses, residual treatment variation and uncertainty.
   Count independent assigning units and eligible future periods.
5. Evaluate heterogeneity or a policy on held-out outcome-based contrasts.
```

### Validation checklist

For each application record the following.

1. **Nuisance prediction.** Compare outcome and treatment losses against design-appropriate baselines on held-out data. In a randomized trial the assignment probability can be known.
2. **Treatment support.** Inspect residual dose variation or arm counts and propensity tails by unit, date and eligible subgroup. Report any restriction and its new target population.
3. **Sensitivity.** Specify the omitted cause or selection mechanism and the change in the effect needed to alter the scientific conclusion.
4. **Interval calibration.** On independent simulated datasets report hits, planned draws, failures, interval width and Monte Carlo uncertainty. Real observational data supply no known counterfactual for coverage.
5. **Cross-validation.** Match folds to the assigning units and information set. Compare the same target and eligible rows across folds or report how they differ.

### Common pitfalls

<WarnBox>

**Pitfall 1: hyperparameter hacking.** Selecting ML hyperparameters that produce the "most significant" treatment effect is a form of p-hacking. Always tune for prediction accuracy on held-out data, not treatment effect magnitude. Never tune hyperparameters to maximize $|\hat{\tau}|$ — this invalidates inference.

**Pitfall 2: ignoring first-stage diagnostics.** If $R^2 < 0.05$ in nuisance estimation, DML variance inflates dramatically. Investigate whether treatment is nearly randomized (good — use simpler methods) or important confounders are missing (bad — results unreliable).

**Pitfall 3: extrapolation without overlap.** DML cannot estimate treatment effects in regions of covariate space where only treated or only control units exist. Check propensity score distributions and trim extreme observations.

</WarnBox>

### An empirical benchmark for 401(k) eligibility and participation

How much does access to an employer's 401(k) plan change net financial assets? In the 1991 Survey of Income and Program Participation, 3,682 of 9,915 records were eligible. Of those eligible, 2,594 participated. No one participated among the 6,233 ineligible records. The companion CSV matches the authors' data in all 14 columns and in row order. See [Chernozhukov et al., Section 6.2, Tables 2–3](https://doi.org/10.1111/ectj.12097).

**Eligibility.** Table 2A estimates the average effect of eligibility, allowing outcome regressions to differ between eligible and ineligible households. Its causal interpretation requires eligibility to be conditionally independent of potential outcomes given the controls and sufficient overlap. The authors keep observations whose estimated propensity lies strictly between 0.01 and 0.99, which can change the population represented in the score. Table 2B fits a partially linear regression (PLR) with a constant eligibility coefficient. Under heterogeneous effects, that coefficient generally weights conditional effects by the conditional variance of eligibility. The paper uses nine controls including income, age and pension status.

**Participation.** Table 3 uses eligibility as an instrument for participation. The IV estimate divides the covariate-adjusted effect of eligibility on assets by its effect on participation. The code trims on the estimated instrument propensity. Under instrument relevance, conditional independence, exclusion, monotonicity and overlap, the ratio identifies the effect for people who participate because their employer offers access. Treating participation directly as a regressor changes the identifying assumptions.

**Repeating the authors' calculation.** For each of the three models we ran their public R estimation routines on 100 fresh twofold partitions and 100 fresh fivefold partitions of the same records. Each of these 600 runs returned seven estimates and standard errors. The original partition assignments were unavailable. The table shows dollar estimates for the two learner families in the companion comparison.
